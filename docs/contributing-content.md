# 내용 기여 가이드 (허브)

메일크래프트의 **내용**(선택지·글귀·모범 메일·점검 항목)을 바꾸는 방법을 모았습니다.
개발을 몰라도 따라 할 수 있게, 각 문서에 **복붙 가능한 예시**를 넣었습니다.

---

## 무엇을 바꾸고 싶나요?

| 하고 싶은 일                        | 가이드                                    | 건드리는 파일                                                 |
| ----------------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| 새 **수신자/톤/포함문구** 추가·수정 | [templates.md](contributing/templates.md) | `lib/types.ts` · `lib/options.ts` · `data/templates.ts` (3곳) |
| 새 **모범 메일** 추가               | [models.md](contributing/models.md)       | `data/models.ts`                                              |
| 새 **점검(체크리스트) 항목** 추가   | [checklist.md](contributing/checklist.md) | `data/checklist.ts`                                           |

---

## 모든 기여에 공통인 규칙

1. **지어내지 않기(날조 금지).** 확인되지 않은 수치·일정·약속·사실을 글귀에 넣지 않습니다.
2. **내부 검토용**입니다. 생성되는 모든 메일은 초안이고, 최종 발송 책임은 작성자에게 있습니다.
3. **세 곳 동기화.** 수신자/톤/문구는 `types ↔ options ↔ templates` key 가 항상 같아야 합니다.
4. **모범 메일의 `reasons`** 는 반드시 채웁니다('왜 모범인가').
5. 저장 전 아래를 돌려 스스로 확인하세요:

   ```bash
   npm run check:content   # 형식 가드(키 일치·reasons 등)
   npm run typecheck       # 타입 검사
   ```

> - 존댓법/높임 수준(예: 어디까지 격식): `[확인 필요]`
> - 금지 표현 목록(쓰면 안 되는 말투·단어): `[확인 필요]`
>
> 이 기준이 정해지면 [tone-review 스킬](../.claude/skills/tone-review/SKILL.md)이 이 문서를 근거로 메일을 점검합니다.

## ⚠️ 가장 중요한 규칙: 사람 리뷰가 최종 관문

- **내용·톤 변경은 반드시 PR(풀 리퀘스트)로 올리고, 리뷰어 승인 후 머지합니다.**
- 자동 검사(형식 가드·타입체크)는 **'형식'만** 봅니다.
  "이 문장이 정말 적절한가"는 **사람이 리뷰**로 판단합니다.
- 절차: [deploy.md](deploy.md) 참고.
