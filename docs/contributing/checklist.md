# 점검(체크리스트) 항목 추가하기

발송 전 3단계에서 보여 줄 점검 항목을 `data/checklist.ts` 에 추가합니다.

> 건드리는 파일: `data/checklist.ts` 한 곳.

---

## 가장 중요한 구분: `assist` vs `self`

| `kind`     | 뜻                                        | 예                                |
| ---------- | ----------------------------------------- | --------------------------------- |
| `"assist"` | **앱이 자동으로 거들 수 있는** 확인       | 빈 제목 감지, 글자 수 안내        |
| `"self"`   | **사람이 눈으로 직접** 봐야 하는 자가확인 | 첨부 누락, 수신자 주소, 사실 여부 |

> 판단 기준: "이 항목을 코드가 기계적으로 검사할 수 있나?"
>
> - 예 → `assist`
> - 아니오(사람의 판단·눈이 필요) → `self`
>
> 지금은 화면에서 라벨(앱 보조 / 자가확인)로만 구분해 보여 줍니다.
> 실제 자동 검사 연결은 추후 확장할 수 있습니다.
>
> **발송 게이트:** 3단계에서 `CHECKLIST` 의 **모든 항목**을 체크해야
> '복사·메일 열기'가 활성화됩니다(`data/checklist.ts` 의 `isChecklistComplete`).
> 항목을 늘리면 그만큼 체크가 더 필요하니, 꼭 필요한 항목만 추가하세요.

---

## 복붙 예시

`data/checklist.ts` 의 `CHECKLIST` 배열에 객체를 **하나 더** 추가합니다.

```ts
{
  id: "no-internal-info",                  // 겹치지 않는 고유 id
  label: "사외로 나갈 내용에 내부 정보가 없는가?",
  kind: "self",                            // 사람이 판단 → self
  hint: "내부 용어·미공개 수치가 섞였는지 확인합니다.",  // 선택
},
```

`assist` 예시:

```ts
{
  id: "subject-length",
  label: "제목이 너무 길지 않은가?",
  kind: "assist",
  hint: "한눈에 들어오는 길이인지 봅니다.",
},
```

---

## 규칙

- `id` 는 **다른 항목과 겹치지 않게** 짓습니다.
- `label` 은 **물음형**으로 쓰면 체크하기 좋습니다("~했는가?").
- `hint` 는 선택입니다. 헷갈릴 수 있는 항목에만 간단히 답니다.
- `kind` 는 반드시 `"assist"` 또는 `"self"` 입니다. (다른 값이면 가드가 막음)

---

## 저장 전 확인

```bash
npm run check:content   # id 중복·잘못된 kind·빈 label 검사
npm run typecheck
```
