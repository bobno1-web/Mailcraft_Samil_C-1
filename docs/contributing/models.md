# 모범 메일 추가하기

팀이 "이렇게 쓰면 좋다"고 합의한 메일을 `data/models.ts` 에 모아 둡니다.
새 모범 메일을 넣을 때는 **`reasons`('왜 모범인가')를 반드시** 채웁니다.
추가한 메일은 **`/models` 화면**에 카드로 자동 표시됩니다(받는 사람·톤 태그 + "왜 모범인가" 목록).

> 건드리는 파일: `data/models.ts` 한 곳.

---

## 한눈에 보는 규칙

- `id` 는 **다른 모범 메일과 겹치지 않는** 짧은 영문 이름(예: `client-deadline-02`).
- `recipient` / `tone` 은 **이미 등록된 key** 만 씁니다. (없으면 먼저 [templates.md](templates.md) 로 추가)
- `reasons` 는 **2개 이상**, 각 항목은 빈 문자열이면 안 됩니다. (안 지키면 가드가 커밋을 막음)
- `reasons` 는 "지어낸 칭찬"이 아니라 **실제 근거**를 적습니다.

---

## 복붙 예시

`data/models.ts` 의 `MODEL_MAILS` 배열에 아래 객체를 **하나 더** 추가하면 됩니다.

```ts
{
  id: "partner-request-01",            // 겹치지 않는 고유 id
  title: "협력사 자료 요청(격식)",       // 목록에 보일 제목
  recipient: "partner",                 // 등록된 recipient key
  tone: "formal",                       // 등록된 tone key
  subject: "[요청] 월간 정산 자료 공유 요청",
  body: [
    "담당자님, 안녕하세요.",
    "",
    "아래와 같이 안내드립니다.",
    "- 지난달 정산 자료 공유를 요청드립니다.",
    "- 양식은 기존과 동일합니다.",
    "",
    "가능하시면 회신 기한을 함께 알려 주시면 감사하겠습니다.",
    "",
    "앞으로도 잘 부탁드립니다.",
    "드림",
  ].join("\n"),
  reasons: [
    "요청 대상과 범위를 한 문장으로 명확히 했다.",
    "추가 확인 없이 바로 처리할 수 있게 양식 기준을 밝혔다.",
  ],
},
```

> **팁:** 본문을 배열 `[ "줄1", "줄2" ].join("\n")` 로 쓰면 줄바꿈 관리가 쉽습니다.
> 한 줄 문자열로 쓰고 `\n` 을 직접 넣어도 됩니다.

---

## `reasons` 를 잘 쓰는 법

좋은 `reasons` 는 **"무엇이, 왜 좋은지"** 를 구체적으로 말합니다.

| 좋은 예                                                | 아쉬운 예     |
| ------------------------------------------------------ | ------------- |
| "요청과 기한을 한 번에 묶어 상대가 할 일을 바로 안다." | "좋은 메일임" |
| "사실만 전달하고 추측을 넣지 않았다."                  | "깔끔함"      |

## 저장 전 확인

```bash
npm run check:content   # reasons 누락·id 중복·잘못된 recipient/tone 검사
npm run typecheck
```
